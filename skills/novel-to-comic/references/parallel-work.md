# 耗时步骤的并行执行

## 模型与启动时机

主代理保留当前模型，不因委派而更换。每个子代理优先显式指定运行时实际可选的最新 Luna 型号，以及该型号支持的最高思考度；若当前环境或运行时中没有 Luna 模型，则使用主代理模型和主代理的思考强度（继承主代理的模型和思考度设置）。优先依据当前工具声明和运行时可用模型信息解析“最新”，不凭命名猜测未提供的型号。

当前工具声明提供的参考配置为 `model="gpt-6-luna"`、`reasoning_effort="max"`；若运行时未提供 Luna 模型，则回退为使用主代理模型和主代理的思考强度（例如 `model="inherit"` 或主代理当前具体型号及其思考强度）。以后运行时提供更新 Luna 时选择更新型号，并查其实际最高思考度，不机械沿用旧型号。调用 `spawn_agent` 或 `invoke_subagent` 的模型覆盖需配合 `fork_turns="none"` 或有限轮数，不能使用不接受覆盖的全历史继承。优先传入明确任务资料，减少无关历史。

在耗时步骤开始前识别可独立执行的任务，按实际并发槽位启动多个子代理，给主代理保留运行名额。例如总槽位为四个时可启动二至三个子代理。后续批次复用已有子代理；复用前确认其模型和思考度仍符合要求。使用当前任务的子代理工具，不为制作分工创建多个用户聊天或同级作品项目。

子代理工具不可用或并发配额耗尽时，报告具体限制，继续由主代理处理可推进的工作。没有 Luna 模型时平滑回退为主代理模型和主代理的思考强度。工具只支持串行生成时，并行安排其他准备工作，不绕过工具约束。并行以独立任务为单位，不能越过全书剧本锁、人物基准或上游状态依赖。

## 分工边界

| 阶段 | 子代理可并行执行 | 必须由主代理处理 |
|---|---|---|
| 原文整理 | 按章节提取原文引句、来源 ID、事实事件、人物出场与状态记录，整理待核实位置 | 亲自读完全部正文，判断事实与歧义、全书结构、因果、人物弧线与改编取舍 |
| 剧本与设定准备 | 按主代理确定的内容整理 JSON、索引、事实档案、引用与文件 | 创作和定稿剧情、对白、分镜、节奏、美术方向、角色设计，完成三类剧本审查 |
| 基准与画格绘制 | 使用主代理定稿的提示词和已通过的真实参考图执行独立生成或指定编辑，保存原始结果 | 设计提示词中的审美内容、挑选基准、看每次图、评估一致性与品味、决定通过或返修 |
| 排版与交付准备 | 按已确定方案整理素材、生成独立缩略图或 PDF 预览，收集机械检查的原始输出 | 页面构图、气泡与视觉层级的取舍，逐页审阅，跨页比较，评估导出结果并最终验收 |

子代理交回事实、文件路径、实际执行记录、原始输出与未完成事项，不输出质量评分、审美推荐、选图排名、通过结论或 `checks: true` 报告。所有涉及审美、品味、评估、审阅的任务都由主代理实际执行；不能通过子代理自检、投票或汇总意见代替。子代理收集的来源记录只是阅读辅助，主代理仍亲自阅读、核实后才登记 `mark-read`。

## 任务文件与共享状态

每个任务写入当前状态目录的 `tmp/workers/<任务ID>/`，成品按统一布局归档在同一作品根目录内部。任务说明至少包含：任务范围与独立 ID、输入文件真实路径、原文来源 ID、当前剧本/参考指纹、主代理确定的提示词或制作方案、允许写入的专属目录、预期输出与停止条件。每次生成任务是一张紧凑合图，格数由 production.md 的画布容量与细节需求决定，可跨成品页面但不共享画格 ID；设定任务可在同一板合并适合的角色/角度/表情/场景道具。主代理规划 canvas_pixels，不把它作为工具尺寸保证。增加并发不会减少调用次数；先提高每次有效内容，再分派独立组。多格合图只调用一次绘图工具，返修也使用统一批次接口。

`project.json` 的原子保存不提供并发读写锁。主代理唯一负责所有会改变项目状态的 helper 命令，包括阅读/来源登记、导入剧本、审查、锁定、参考登记、尝试登记、compose、export 和 complete；子代理不得运行这些命令或直接修改该文件。子代理可读取原文和固定输入，不改共享剧本、参考图、提示词或已登记成果。

画格批次采用以下顺序：
1. 主代理确认有效剧本锁与人物基准，排除已通过格和 pending 格，定稿各组的画布容量、紧凑格区和逐格提示词；先 `preflight --plan`，部分复用则重排和重写提示词，串行执行 `begin-batch`，分配互不重叠的生成组、实际画格 ID 和真实尝试号。全部复用时不派发生成。
2. 子代理各自按指定输入调用内置绘图工具，把每次实际输出和工具错误写到专属目录；只执行分配的一次尝试，不自行重试或改变提示词、参考及模型服务。立即保存该次工具返回的真实输出路径/提示（如 output_hint）和工具记录，并复制对应文件；不得从共享输出目录按时间挑最新文件，不得以空的 isError 或其他任务的图像替代本次真实输出。
3. 主代理查看每次合图，确认真实格界后执行 `split-batch`；查看每张裁切图和成品阅读尺寸，核对原文、参考、原生细节与输入指纹，逐格亲自编写 QA，再串行 `finish-panel` 或 `fail-panel`。合格格保留，适合的失败格重新组成紧凑返修组，像素不足或复杂局部编辑则拆小组或单格；工具错误也给组内实际画格逐一结算，不漏记尝试。

同一批次进行期间保持所用剧本、提示词与基准不变。必须修改时停止受影响任务；已经启动的真实尝试保留记录和原始结果，过期输出不能直接登记为当前通过图。主代理审阅本批次并登记后再派发依赖其结论的任务；新的有效输入仍遵守三次尝试上限。

## 汇总与恢复

主代理汇总文件和实际执行记录，检查缺失、输入版本与工具失败，再亲自完成相应语义或视觉审查。子代理的结果不能自动触发 `review`、`register-reference`、`review-layout` 或 `complete`。

保存任务范围、真实模型/思考度、输入版本、输出路径及执行状态到项目内部，便于中断后定位。子代理未返回、工具调用未完成或主代理未审阅时明确记录待办，不视为完成，不重复启动仍在运行的同一画格尝试。
