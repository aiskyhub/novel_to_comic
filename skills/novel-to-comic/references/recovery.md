# 中断、续做与变更

开始时定位原有书名顶层目录及对应卷子目录，执行 status，依据真实文件、指纹和实际验收记录判断下一项，不相信“最后画到第几章”的手写说明。项目文件原子保存，原稿不覆盖。续做、失败重试和返修沿用已有卷目录，不创建同级的“续作”“重做”“最终版”项目。

阶段恢复：未完成阅读先补读；未完成全书稿先补稿；审查不齐或过期先重审；锁无效先解决再绘图；锁有效后复用已验收且输入一致的画格，处理 pending/failed/rejected 和缺失成果。

正在生成的 pending 尝试不能重开一次。从 status.batches 定位批次 ID、规划画布、登记提示词、原图真实尺寸和各格状态，不从共享目录猜输出。有原图则查看并执行 split-batch，再逐格 QA/finish-panel；只有工具返回路径时先归档。确实失败则给组内各 pending 格 fail-panel 记录原因。已通过兄弟格直接复用；未通过格按参考、场景、修复目标和细节需求重新组成紧凑批次，可合并多个适合的失败格，不重绘合格格或保留旧空区。像素不足或复杂局部编辑拆小组或单格。若生成期间剧本/参考变动，保留图像，用 fail-panel --outcome stale --reason 实际原因关闭旧 pending；取消任务用 cancelled。结算不要求有效锁，finish-panel 仍要求锁和视觉输入一致。关闭旧任务不能重置三次上限。

变更影响：
- 原稿内容或来源索引变化：旧锁失效；保留已有状态与成果，在当前卷目录的 `versions/<版本标识>/` 下用 init 重新提取、阅读和审查，不手改原文 ID，不创建同级新项目。该子目录是新版本的状态目录，后续命令的 `--project` 指向它；其工作文件与成果也保存到该版本内部。在该卷目录保存简短的 `versions/current.json`，记录当前状态目录的相对路径、原文变更原因及旧状态位置，以便下次定位。初始状态可继续保留在该卷目录根部，不为整理而强行移动或改写其路径和指纹。
- 剧本改变：三类报告需要对应新版本；重新锁定前不出图。
- 人物、画风、场景、镜头或状态改变：关联参考/画格按输入指纹失效。重新登记/绘制受影响成果。
- 只有对白或页布局改变：重新审查锁定，复用视觉输入相同的绘图，再排版和检查导出。
- 图片、提示词或交付文件缺失/更改：不再算完成，恢复或重新检查生成。

三次失败只针对同一画格的同一视觉输入版本。不得通过微小改词或更换无关 ID 规避上限。重大输入调整须有实际修复依据。

工具不可用/限额时保存阻塞原因、待办与原始输出，停止依赖该工具的步骤；可完成独立文本检查。不要声称应用关闭后还在运行，用户明确要求后才配置调度。


仅支持新版 schema_version=4 数据。其他版本明确拒绝，不提供迁移，也不修改或补验收已有旧项目。新版项目中的新参考使用 register-reference 独立登记，再明确重绑受影响画格；旧记录保留，输入不变且仍有效的已验收画格正常复用。

归档原稿是制作输入。外部原稿移走不阻塞已归档项目，外部内容变化会在 status 中提示重新提取；归档输入缺失或改变仍使来源关卡失效。不能制造原稿副本或声称已核验缺失文件。原文范围或提取本身有未解决问题时仍须处理来源关卡。

页面缓存损坏时 compose 归档异常候选并重新渲染，旧 QA 失效；实际查看修复页再登记。字体变化生成新的布局指纹与导出路径，不与旧字体成品混为一个版本。

维修归档及其真实指纹保留在 cache_repairs 记录中，导出验证同时检查归档完整性。归档缺失、内容变化或有未登记的维修文件时先核实并修复记录，不删除历史来放行。

批次原图在像素门槛失败时也归档，rejected_panels 不代表已结算；主代理仍逐格记录失败。split-batch 可归档和提取旧输出，即使全书锁已过期；qa-inputs/finish-panel 仍必须有有效锁和一致输入，过期结果不能直接验收。恢复时先读取原记录，不重复 begin-batch 或增加尝试。已登记原图与裁切区域不可替换；新生成/编辑结果必须有新批次和尝试。
