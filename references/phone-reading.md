# 手机单页尺寸与可读性（正文制作必读）

默认交付是竖屏单页漫画：一张成品图按手机可视宽度显示时占约一屏，连续阅读时不出现一屏挤下两三张完整页面。此规范同时用于分镜、生成提示词、原图验收、整页验收与阅读器；不是只改导出分辨率。

## 成品画幅

| 项目 | 约束 |
|---|---|
| 默认画布 | `format=pages`，`width=1080`，`height=2400`，宽高比 **9:20** |
| 其他单页尺寸 | 高/宽必须在 **2.0–2.4**；如 1080×2160、1440×3200，字号按宽度同比调整 |
| 正文格数 | 普通页 **3–5 格，默认 3 格**；重点页 1–3 格。每行一格、整宽纵排，禁止双列小格或 2×2 网格 |
| 页边与格距 | 在完整页提示词中指定窄边距；每页可用高度内的画格面积至少占 **85%**，多余底部空白不得超过可用高度的 15% |
| 整页构图 | 原图与计划画格比例一致；整页内的镜头自然占满布局，不得靠大白边填页 |
| 显示方式 | 图片占满阅读区宽度，等比显示完整内容；禁止多列缩略图、定高裁切、拉伸、把几页拼成一张短宽图 |

1080×2400 在 360 CSS 像素宽时约高 800 CSS 像素，在 390 宽时约高 867，在 430 宽时约高 956。占一屏是阅读节奏目标，不是保证所有设备物理屏幕完全吻合；浏览器栏、阅读器栏与设备比例不同，可允许少量纵向滚动，保留完整画面。

每格高度在编剧时确定，`aspect_ratio=画格宽/画格高`用于完整页提示词。默认三格可约占可用高度的35%/32%/33%，由绘图工具直接完成整页边框与格距；不设额外程序标题区，不在生成后重新排格。景别与大小服务原著，不必等分；四、五格仍纵排，放不下清楚的气泡就延续到下一页，不能缩字省页。

## 原生文字与生成容量

- 默认 `font_size=54`；1080 宽画布的正文、对白与旁白 **至少 48 像素**，建议 54–60。拟声可更大，所有需读懂的正文都不得低于底线。
- 按最终整页缩放计算：`手机显示字高 = 成品图中字高 × 手机显示宽度 / 成品图宽度`。在 **360 CSS 像素**宽的最小验收视口中，正文实际字高不得低于 **16 CSS 像素**，目标 18–20；390、430 宽也要复查。1080 宽画布的 48/54/60 像素分别对应 16/18/20 CSS 像素。
- `font_size` 是生成提示词的排字目标，脚本不为原生气泡贴字。实际文字大小必须看图核查，不能以 JSON 写了 54 就宣称合格。工具返回宽度与请求目标不同时，按真实整页宽度同比核查字高，图片保持原始字节不重新排版。
- 气泡留足内边距和行距；正文用清晰中文字体，文字与底色有稳定对比。长对白按原文的自然语义分气泡、分格或延续下一页，保留信息与说话顺序；禁止缩字、删剧情、把重要旁白改成脚注小字。
- **一页一次生成，一次交付完整页**。提示词包括本页全部格区布局、人物、背景、原样文字和气泡；画幅是请求目标，实际输出高/宽须2.0–2.4、原生宽至少800。不得把页面拆成独立绘图任务，不额外试画、生成备选图或变体。
- 文字与构图过密时在编剧和提示词打磨阶段调整镜头格高、气泡位置或增加后续完整页，并按正常流程重审锁定；不得生成后通过拆图或拼贴解救。失败按完整页返修，遵守每页三次调用预算。

## 验收与报告

1. `check-script` 检查单页比例、字号目标、每页 1–5 格和纵向单列；`prepare-pages` 复查这些约束，整页构图占幅由主代理直接看整页核查。尺寸约束在出图前规划，不能等失败后临时缩低成品尺寸。
2. `prepare-pages` 为每张完整原生页自动保存 **360、390、430 CSS 像素宽**的等比PNG预览到 `pages/phone-previews/`，路径与哈希写入 `layout.pages[].phone_previews`，`verify-export` 检查文件与尺寸。按预览实际尺寸阅读，不放大；核对最小正文、说话人、旁白、表情和动作。缩略图接触表或原图放大查看不能代替该检查。
3. 页面 QA 必须包含 `phone_readability=true` 与 `phone_reading_notes`：逐页记录页 ID、真实尺寸、三种预览宽度、最小正文显示字高、具体对白/旁白的观察及发现与修复。`min_body_css_px`取360宽下的最小实际字高；没有任何文字的纯画面页填null并注明，含文字的页不得填null。它是实际看图的记录，脚本只核验字段和数值，不能证明已看图或正确测字。
4. 必须同时检查占屏与可读性。细节丰富但文字小、画布够高但漫画只挤在上半页、用空白或拉伸占屏，都不通过。最终阅读器按宽度显示，同样核查无需捏合放大即可读正文。

正文只交付完整竖屏单页，不保留其他图片重组生产模式。

## 网上规范与本技能决策的边界

以下为 **2026-10-06** 核查的官方资料；平台投稿时重新确认实时限制。

- [WEBTOON 官方：长图自动切片](https://m.webtoons.com/en/notice/detail?noticeNo=1766)：上传长图会按最大 800×1280 像素优化并切片。这是上传切片限制，**不是**一张完整手机漫画页的推荐宽高比。仅用来区分平台上传限制与手机单页标准；本技能正文制作不使用切片流程。
- [Tapas 官方：File Size Overview](https://help.tapas.io/hc/en-us/articles/360052100813-File-Size-Overview)：漫画页宽 940 像素，普通静态图不限制高度；GIF 高度限制另算。说明移动漫画不存在统一的单页高度，平台宽度与阅读节奏应分开考虑。
- [CLIP STUDIO 官方手册：Webtoons](https://help.clip-studio.com/en-us/manual_en/540_comic/Webtoons.htm)：提供手机可视区域框与切片导出工具，用可视框检查手机上实际显示的部分。
- [CLIP STUDIO 官方：手机预览](https://support.clip-studio.com/en-us/faq/articles/20220037)：可在手机 Companion mode 中预览制作中的条漫。

**1080×2400、2.0–2.4 的高宽比、正文 16 CSS 像素底线、纵排和占幅阈值是本技能为用户手机阅读制定的制作与验收约束，不能称为 WEBTOON、Tapas、CLIP STUDIO 或 WCAG 的通用标准。** 屏幕阅读不靠 DPI/300dpi 或单纯增加像素解决，必须一起调整构图与缩放后的字高。
