# 整页生产恢复与修订

续做先status定位当前卷、有效锁、next_page、art.pages尝试账本、实际提示词和已验收整页。项目统一采用标准 Schema v6 进行管理。

pending页不能重新begin-page。已有工具结果时继续查看同一整页，qa-inputs后整页验收；没有结果则等待原调用。若生图调用失败（工具报错、网络超时、API异常），允许最多重试六次（通过 fail-page --generation-failure 记录）。若连续六次均报错无法出图且重试机会耗尽，绝对禁止流水线停工或死锁，使用 placeholder-page 自动生成标明失败诊断、保留剧本分镜剧情与台词的 1080×2400 原生失败占位图，加 --finish 标记为 placeholder_pending 暂存入库，无缝推进下一页生产。占位图允许打包内部预览包，但正式交付（complete）时默认严格拦截，除非用户显式指定 --allow-placeholders 授权。确实失败/取消/输入过期，使用fail-page记录真实原因，已有输出用--file归档。失败结算可在锁失效后执行；通过验收必须有有效锁和一致页输入。

重试仍是一张完整页，先修订完整提示词中的具体缺陷，再begin-page进行下一次调用。文字错误、人物漂移、镜头遗漏、格数错误和尺寸/阅读问题都在同一整页内修复。已通过的其他页直接复用。微调提示词不刷新每页三次审图预算，不重复生成已经存在的pending结果。**【三绘即决铁律】单页累计三次审图均未达完全合格标准时，严禁发起第四次重绘，也绝对禁止停工等待外部介入！** 必须立刻启动兜底择优机制：对比三次尝试，选择其中一张最符合标准的图片，并在 QA 报告中详细解释该图片的缺陷处（写入 defect_explanation），由主代理执行 finish-page 暂存入库为 accepted_flawed（三次之前机械门禁严禁带缺陷放行；含 unresolved critical 缺陷直接标记为 blocked 阻断）。accepted_flawed 状态解除生产卡点、允许继续推进后续页面生产，但在最终 complete 交付时将被门禁拦截，除非用户显式通过 --allow-flawed 明确授权交付。

剧本、对白、页面分镜顺序、构图、角色状态或有效参考改变时，按set-script→三轮审查→lock-script重新确认；只有实际输入未变的完整页能复用。字号或气泡规范改变会使含原生文字的页失效，不能只换数据说明。输出文件或提示词哈希变化同样使该页失效。

外部原稿变动仅作为警告，制作依归档副本；归档原文变化阻断原有锁定。需要重新提取原文时，在当前卷versions/下建立新的独立状态，维护current.json指向真实新状态。全部作品说明的剧情仍必须来自实际已读原文。

prepare-pages可重新复制有效整页与恢复手机预览；该过程不绘制内容、不消耗生图额度。之后实际看页、review-layout、export、verify-export。区分机械完整性与真实人工阅读结论。

## 成品资产保护与删除二次确认铁律

1. **成品文件与已完成成品图禁止乱删**：
   - 导出到 `exports/` 目录的全部成品文件（包括但不限于离线 HTML 阅读器 `reader.html`、全卷高画质 PDF `comic.pdf`、标准 CBZ 漫画包 `comic.cbz`）以及已验收完成的整页成品图（`art/pages/`、`pages/` 等成品图像资产），为漫改流水线的核心交付成果，**绝对禁止任何形式的随意删除、擅自清空或静默覆盖**。
   - 无论是在单页返修、重新执行 `prepare-pages` 或 `export`、版本更新迭代、异常恢复还是日常清理中，已有成品文件及成品图均必须完整保留。`exports/` 目录按输入指纹独立隔离保存，严禁擅自抹除历史版本成品。
2. **删除唯一触发条件——用户明确要求**：
   - 严禁任何代理或自动化脚本自行推定“文件已过期”或“空间清理”而擅自删除成品文件或成品图。只有且仅当用户主动、明确要求删除时，才可进入删除流程。
3. **强制二次确认机制**：
   - 即使用户明确要求删除成品文件或成品图，主代理/总导演**绝不得直接执行物理删除**，必须停下来主动向用户发起**二次确认**：
     - 清晰列出拟删除的文件路径、所属卷次与已完成成品图的具体页码清单；
     - 严肃说明该删除操作不可逆，画面与排版将永久丢失，无法自动恢复；
     - 明确向用户确认：“检测到您要求删除已完成的成品图/exports 成品文件。请确认：是否确认删除已完成的成品图及相关成品交付文件？”；
     - **必须在获得用户明确二次肯定答复（如“确认删除”）后方可执行物理删除**；若用户犹豫、未明确答复或表示保留，必须立即终止删除操作并完整保留原文件。
